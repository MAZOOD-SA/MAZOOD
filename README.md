# مزوّد (Mazood)

منصة B2B تربط مصانع مدينة سدير الصناعية بمزوّدين موثّقين: المصنع يرفع طلب، والمزوّدين يرسلون عروض، والمصنع يقبل عرض واحد، وتوصله فاتورة موحّدة.

من كود واحد يطلع **الموقع** و**تطبيق iPhone** و**تطبيق Android**، ومعهم **الخادم** اللي يحفظ البيانات ويطبّق الصلاحيات.

> **الحالة الحالية: المرحلة ٢٫٥.** دخول حقيقي برقم الجوال ورمز التحقق، وطلبات المصنع تنحفظ في قاعدة البيانات، مع تخزين محلي للسرعة، وجدول صلاحيات، وحماية على مستوى قاعدة البيانات. المزوّدين والعروض للحين وهميين (وضع التجربة)، وشاشات المزوّد في المرحلة ٣ و٤. التفاصيل في [`PLAN.md`](PLAN.md).

## المتطلبات على جهازك

- **Node.js 22** أو أحدث
- **pnpm 10** (فعّله بالأمر `corepack enable`)
- **Docker** (لقاعدة البيانات على جهازك). أو PostgreSQL 16 مثبّت مباشرة.
- للتجربة على الجوال: تطبيق **Expo Go** من App Store أو Google Play

## التشغيل خطوة بخطوة

**١. ثبّت المكتبات:**

```bash
pnpm install
```

**٢. شغّل قاعدة البيانات** (تنشئ قاعدتين: وحدة للتطوير ووحدة للاختبارات):

```bash
docker compose up -d db
```

**٣. جهّز إعدادات الخادم.** أنشئ الملف `apps/api/.env` بهذا المحتوى (للتطوير على جهازك بس):

```bash
APP_ENV=development
DATABASE_URL=postgresql://mazood:mazood_dev@localhost:5432/mazood_dev
OTP_SECRET=اكتب-هنا-٣٢-حرف-عشوائي-على-الأقل
OTP_EXPOSE_IN_RESPONSE=true
DEMO_MODE=true
CORS_ORIGINS=http://localhost:8081
```

شرح كل متغير في [`.env.example`](.env.example). الملف `.env` ما يدخل المستودع أبدًا.

**٤. أنشئ جداول قاعدة البيانات:**

```bash
pnpm db:migrate
```

**٥. شغّل الخادم** (في نافذة):

```bash
pnpm api
```

**٦. شغّل التطبيق** (في نافذة ثانية):

```bash
EXPO_PUBLIC_API_URL=http://localhost:3000/api/v1 pnpm web
```

افتح `http://localhost:8081`. اكتب أي رقم جوال سعودي، والرمز يظهر على الشاشة (لأن `OTP_EXPOSE_IN_RESPONSE=true`)، ويطلع كمان في سجل الخادم.

**على الجوال:** شغّل `EXPO_PUBLIC_API_URL=http://<عنوان-جهازك-في-الشبكة>:3000/api/v1 pnpm start`، وامسح رمز QR بكاميرا الجوال (iPhone) أو من داخل Expo Go (Android). لازم الجوال والكمبيوتر على نفس الشبكة.

### وش تجرّب

1. ادخل برقم جوال، واكتب الرمز، واكتب اسم المصنع وموقعه.
2. ارفع طلب. بعد ٥ ثواني يوصل عرضين من مزوّدين وهميين.
3. اقبل عرض. تقدر تلغي مجانًا لين يبدأ المزوّد (الوهمي يبدأ بعد دقيقة).
4. بعد ما يبدأ: «اطلب الإلغاء»، والمزوّد الوهمي يوافق بعد ١٠ ثواني. أو «تأكيد الاستلام».
5. سكّر الصفحة وارجع: الجلسة والطلبات محفوظة.

## الاختبارات (أمر واحد)

قاعدة البيانات لازم تكون شغّالة (الخطوة ٢)، وبعدها:

```bash
pnpm test
```

الأمر يسوي خمس خطوات بالترتيب، ويوقف عند أول خطأ:

1. يعيد توليد الثيم من `brand/tokens.json`.
2. يتأكد إن ما فيه أي لون مكتوب مباشرة في الكود.
3. يفحص أنواع TypeScript (التطبيق والخادم).
4. يمسح قاعدة الاختبارات `mazood_test` وينشئها من جديد.
5. يشغّل الاختبارات: الهوية، والمبالغ والضريبة، والتنسيق، وقواعد الطلب والإلغاء، و**جدول الصلاحيات لكل دور**، و**الخادم**: حماية قاعدة البيانات (RLS)، وجلسة الموقع وحماية CSRF، و«أجهزتي»، الدخول برمز التحقق، وحدود المحاولات، والجلسات، وإن المصنع ما يشوف طلبات مصنع ثاني، وقبول عرض واحد بس حتى لو انضغط مرتين بنفس اللحظة، والإلغاء قبل وبعد بدء التنفيذ.

لو قاعدة الاختبارات في مكان ثاني: `TEST_DATABASE_URL=... pnpm test`.

## النشر

المنصة كلها (الخادم والموقع) **حاوية Docker وحدة**، تشتغل عند أي مزوّد استضافة يدعم Docker، ومنهم المزوّدين داخل السعودية.

**١. ابنِ الحاوية:**

```bash
docker build -t mazood .
```

**٢. جهّز قاعدة بيانات PostgreSQL 16** عند مزوّد الاستضافة، وخذ عنوانها (`DATABASE_URL`).

**٣. حط الإعدادات في لوحة الاستضافة** (مو في ملف). الأسماء والشرح في `.env.example`. أقل شي:

| المتغير | العنوان التجريبي (staging) | المنصة الحقيقية (production) |
| --- | --- | --- |
| `APP_ENV` | `staging` | `production` |
| `DATABASE_URL` | من الاستضافة | من الاستضافة |
| `OTP_SECRET` | جديد وعشوائي | جديد وعشوائي، مختلف عن التجريبي |
| `TRUST_PROXY` | `true` | `true` |
| `DEMO_MODE` | `true` | ممنوع (الخادم يرفض يشتغل) |
| `OTP_EXPOSE_IN_RESPONSE` | `true` | ممنوع |
| `SMS_PROVIDER` | `console` | مزوّد حقيقي (ما انقرر، سؤال ٥) |

**٤. شغّل الحاوية** على المنفذ `3000`. أول ما تشتغل تطبّق ترحيلات قاعدة البيانات بنفسها، وبعدها تشغّل الخادم.

> **مهم:** مستخدم قاعدة البيانات اللي يتصل فيه الخادم **لازم ما يكون superuser**، لأن هذا يتجاوز حماية قاعدة البيانات (RLS). أغلب مزوّدين قواعد البيانات المُدارة يعطونك مستخدم عادي، وهذا المطلوب.

**٤٫٥. أسّس أول مالك للمنصة** (مرة وحدة بعد أول نشر)، برقم جوال مخصص لحساب الإدارة (مو رقم مستخدم كمصنع):

```bash
pnpm --filter @mazood/api staff:grant 05XXXXXXXX owner
```

**٥. تأكد إنها شغّالة:** افتح `https://<العنوان>/api/v1/health`، لازم يرجع `{"ok":true}`.

> **العنوان التجريبي:** ببيانات وهمية بس، ممنوع بيانات عملاء حقيقيين (القرار ٨ في `docs/decisions.md`). والانتقال للنطاق الرسمي يكون بربط النطاق في لوحة الاستضافة، بدون أي تعديل في الكود.

**التطبيقين (iPhone وAndroid)** يحتاجون حساب Expo باسم الشركة، ويُنشرون في المرحلة ٨.

## قواعد لازم تمشي عليها

- **الصلاحيات في الخادم، مو في الواجهة.** أي بيانات تخص مصنع لازم تنفلتر برقم مصنعه داخل `apps/api/src/services/`. والطلب لمصنع ثاني يرجع ٤٠٤ (مو ٤٠٣).
- **قواعد الطلب في مكان واحد:** `packages/shared/src/requests.ts`. الخادم يطبّقها، والتطبيق يعرض الأزرار حسبها. لا تكتب شرط حالة جديد في شاشة.
- **التحقق من المدخلات:** كل مدخل جديد له قاعدة Zod في `packages/shared/src/schemas.ts`، والخادم يرفض أي شي ما يطابقها.
- **أي إجراء يغيّر حساب أو طلب أو مبلغ يُسجَّل** في سجل الإجراءات (`audit()` في `apps/api/src/audit.ts`). السجل ما ينعدّل ولا ينحذف.
- **ولا لون مكتوب مباشرة في الكود.** الألوان من `useTheme().colors` فقط. لتغيير لون: عدّل `brand/tokens.json` و`brand/tokens.css` ثم شغّل `pnpm tokens`.
- **زر accent (كهرماني) واحد بس في كل شاشة**، للإجراء الأهم.
- **المبالغ بالهللة كأرقام صحيحة.** لا تستخدم كسور للفلوس.
- **كل نص في الواجهة** يُكتب في `apps/app/src/i18n/strings.ts` بالعربي والإنجليزي، وبنبرة `BRAND.md`.
- **أي مفتاح سري** مكانه إعدادات الاستضافة، واسمه في `.env.example`. ممنوع في الكود، وممنوع في أي متغير يبدأ بـ `EXPO_PUBLIC_`.
- **تغيير في قاعدة البيانات:** عدّل `apps/api/prisma/schema.prisma`، وبعدها `pnpm db:migrate` (ينشئ ملف ترحيل جديد ويحدّث عميل Prisma، ارفع ملف الترحيل مع الكود).
- **مسار جديد في الخادم:** أول سطر فيه `requirePermission(req, "...")` بصلاحية من `packages/shared/src/permissions.ts`. وإذا يخص بيانات مصنع، يشتغل داخل `withFactoryScope` (شوف `routes/requests.ts`).
- **جدول جديد فيه بيانات مصنع:** أضف له سياسة RLS في ترحيل، مثل ترحيل `row_level_security`.
- **مكتبة جديدة:** سجّلها مع رخصتها في `docs/licenses.md`.

## هيكل المجلدات باختصار

```
apps/app/            الواجهة: الموقع والتطبيقين (Expo + Expo Router)
  app/               الشاشات (كل ملف = صفحة)
  src/api/           الاتصال بالخادم، والجلسة
  src/components/    المكوّنات المشتركة (الأزرار، والبطاقات...)
  src/i18n/          النصوص بالعربي والإنجليزي، ورسائل الأخطاء
apps/api/            الخادم (Fastify + PostgreSQL)
  src/routes/        المسارات (الدخول، والمصنع، والطلبات)
  src/services/      منطق الطلبات، مع فلترة كل شي برقم المصنع
  prisma/            شكل قاعدة البيانات وملفات الترحيل
  test/              اختبارات الخادم
packages/shared/     القواعد المشتركة بين الخادم والتطبيق
packages/brand/      الثيم المولّد من brand/tokens.json
brand/               ملفات الهوية (المرجع، لا تُعدّل بدون موافقة)
docs/                التوثيق
```

التفاصيل الكاملة في [`docs/architecture.md`](docs/architecture.md).
