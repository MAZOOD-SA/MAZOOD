# مزوّد (Mazood)

منصة B2B تربط مصانع مدينة سدير الصناعية بمزوّدين موثّقين: المصنع يرفع طلب، والمزوّدين يرسلون عروض، والمصنع يقبل عرض واحد، وتوصله فاتورة موحّدة.

من كود واحد يطلع **الموقع** و**تطبيق iPhone** و**تطبيق Android**.

> **الحالة الحالية: المرحلة ٣.** الدخول الحقيقي، وطلبات المصانع، وتسجيل المزوّدين ورفع مستنداتهم، ولوحة الإدارة للتوثيق والموظفين. العروض والفواتير للحين ببيانات وهمية. التفاصيل والمراحل الجاية في [`PLAN.md`](PLAN.md).

## المتطلبات على جهازك

- **Node.js 22** أو أحدث
- **pnpm 10** (فعّله بالأمر `corepack enable`)
- للتجربة على الجوال: تطبيق **Expo Go** من App Store أو Google Play

## التشغيل خطوة بخطوة

```bash
pnpm install
```

```bash
pnpm web
```

بعدها افتح الرابط اللي يطلع (عادةً `http://localhost:8081`). بهذي الطريقة يشتغل **الوضع التجريبي**: أي رقم جوال سعودي وأي رمز من ٦ أرقام يدخلك، والبيانات وهمية.

### تشغيل الخادم (الوضع الحقيقي)

في نافذة طرفية أولى:

```bash
pnpm api
```

الخادم يشتغل على `http://localhost:3001` بقاعدة بيانات تجريبية داخل الذاكرة (تنمسح كل مرة)، **ورمز التحقق يطلع في هذي النافذة** بدل رسالة نصية. وللتشغيل على PostgreSQL حقيقي حدّد `DATABASE_URL` (شوف `apps/api/.env.example`).

في نافذة ثانية، شغّل الواجهة موجّهة للخادم:

```bash
EXPO_PUBLIC_API_URL=http://localhost:3001 pnpm web
```

سجّل برقم جوالك، وخذ الرمز من نافذة الخادم، وارفع طلب. أقفل الصفحة وافتحها: الطلب والجلسة يرجعون.

### تجربة المزوّد ولوحة الإدارة

شغّل الخادم مع رقم يصير «مالك» على القاعدة التجريبية:

```bash
DEV_OWNER_PHONE=0599000000 pnpm api
```

1. من شاشة الدخول اضغط «مزوّد خدمة؟ سجّل من هنا»، وسجّل برقم ثاني، وعبّ البيانات، وارفع مستندين (أي PDF أو صورة)، وأرسل للتوثيق.
2. اطلع، وادخل بالرقم `0599000000`. توصل للوحة `/admin`، ووثّق المزوّد.

**أول مالك في الإنتاج** يُضاف من الخادم: `pnpm api:add-staff -- <الجوال> owner "<الاسم>"`. بعده كل الموظفين من اللوحة.

### إعدادات المنصة (المرحلة ٤)

صلاحية العرض، ومدة الطلب، وأقصى عروض، وسياسة الإلغاء، وغيرها: محفوظة في قاعدة البيانات، وتتغيّر بدون إعادة تشغيل. القيم الافتراضية وشرح كل واحد في `packages/shared/src/settings.ts`.

```bash
pnpm api:set-setting                                  # يعرض كل الإعدادات الحالية
pnpm api:set-setting -- offerValidityHours 24         # صلاحية العرض ٢٤ ساعة
pnpm api:set-setting -- cancellation '{"responseHours":24,"feeHalalas":0}'
pnpm api:set-setting -- commitment '{"enabled":true,"windowMonths":12,"minOrders":5}'   # رقم «التزم بـ X من Y طلب»
```

كل تعديل ينكتب في سجل الإجراءات. (الأمر يشتغل على قاعدة البيانات اللي في `DATABASE_URL` أو `PGLITE_DIR`. القاعدة اللي في الذاكرة تنمسح مع كل تشغيل.) وتعديلها من لوحة الإدارة يجي في المرحلة ٦.

## خريطة الكود (Graphify)

لتقليل وقت البحث في الكود (ولتقليل استهلاك التوكن مع Claude Code): ثبّت Graphify مرة وحدة (`pipx install graphifyy==0.9.115`)، وبعدها:

```bash
pnpm map
```

يبني خريطة في `graphify-out/` (محليًا وبدون تكلفة). اقرأ `graphify-out/GRAPH_REPORT.md`، أو اسأل: `graphify query "وين يتحدد المصنع في الطلبات؟"`.

**على الجوال:** شغّل `pnpm start`، وامسح رمز QR بكاميرا الجوال (iPhone) أو من داخل Expo Go (Android). لازم الجوال والكمبيوتر يكونون على نفس الشبكة.

## الاختبارات (أمر واحد)

```bash
pnpm test
```

الأمر يسوي أربع خطوات بالترتيب، ويوقف عند أول خطأ (يغطّي الواجهة والخادم):

1. يعيد توليد الثيم من `brand/tokens.json`.
2. يتأكد إن ما فيه أي لون مكتوب مباشرة في الكود.
3. يفحص أنواع TypeScript (الواجهة والخادم).
4. يشغّل اختبارات Vitest: الهوية، والمبالغ والضريبة، والتنسيق، ومنطق الطلبات والعروض، **والدخول والصلاحيات في الخادم** (على PostgreSQL داخل العملية، بدون تثبيت شي).

## النشر

**الخادم:** يتشغّل بـ `NODE_ENV=production` مع المتغيرات في `.env.example`، وبأمر `pnpm --filter @mazood/api start`. في الإنتاج يرفض يبدأ إذا نقص `DATABASE_URL` أو `AUTH_SECRET` أو `CORS_ORIGINS`، أو إذا كان مزوّد الرسائل `console`. **مكان الاستضافة ما انقرر** (سؤال ٤ في `PLAN.md`).

**الواجهة:** الموقع ملفات ثابتة (static). تُبنى بالأمر (مع عنوان الخادم): تُبنى بالأمر:

```bash
EXPO_PUBLIC_API_URL=https://عنوان-الخادم pnpm build:web
```

والناتج في `apps/app/dist`، ويُرفع على أي استضافة ملفات ثابتة. الاستضافة الرسمية ونشر التطبيقين في المتاجر ما انقرروا للحين، لأنهم يحتاجون حسابات باسم الشركة (شوف `docs/services.md`).

## قواعد لازم تمشي عليها

- **ولا لون مكتوب مباشرة في الكود.** الألوان من `useTheme().colors` فقط، والاختبار يفشل لو لقى `#xxxxxx` أو `rgb(...)`. لتغيير لون: عدّل `brand/tokens.json` و`brand/tokens.css` ثم شغّل `pnpm tokens`.
- **زر accent (كهرماني) واحد بس في كل شاشة**، للإجراء الأهم.
- **المبالغ بالهللة كأرقام صحيحة** (`src/lib/money.ts`). لا تستخدم كسور للفلوس.
- **كل نص في الواجهة** يُكتب في `apps/app/src/i18n/strings.ts` بالعربي والإنجليزي، وبنبرة `BRAND.md`.
- **أيقونة جديدة:** أضفها في `apps/app/src/components/icons.ts` (من Tabler Icons).
- **مكتبة جديدة:** سجّلها مع رخصتها في `docs/licenses.md`.

## هيكل المجلدات باختصار

```
apps/app/          الواجهة: الموقع والتطبيقين (Expo + Expo Router)
  app/             الشاشات (كل ملف = صفحة)
  src/components/  المكوّنات المشتركة (الأزرار، والبطاقات...)
  src/data/        المخزن: بيانات وهمية (تجريبي) أو من الخادم (حقيقي)
  src/api/         الاتصال بالخادم وحفظ الجلسة
  src/i18n/        النصوص بالعربي والإنجليزي، والاتجاه
  src/lib/         المبالغ والتنسيق
  src/theme/       الوضع الفاتح والداكن
apps/api/          الخادم (Fastify) وقاعدة البيانات (migrations/) ومسارات routes/
packages/shared/   قواعد التحقق والأقسام المشتركة بين الواجهة والخادم
packages/brand/    الثيم المولّد من brand/tokens.json
brand/             ملفات الهوية (المرجع، لا تُعدّل بدون موافقة)
scripts/           أدوات الفحص
docs/              التوثيق
```

التفاصيل الكاملة في [`docs/architecture.md`](docs/architecture.md).
