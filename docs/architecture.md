# البنية التقنية

**آخر تحديث:** 22 نوفمبر 2026 (المرحلة ٢)

## الصورة العامة

```
  الموقع ──┐
  iPhone ──┼──► apps/app (Expo + React Native)
  Android ─┘        │  كود واحد للثلاثة
                    │
                    │ HTTPS  /api/v1/...   (رمز الجلسة في رأس Authorization)
                    ▼
              apps/api (Node + Fastify) ──► PostgreSQL (Prisma)
                    │
                    ├── يقدّم الموقع من نفس العنوان
                    ├── مزوّد الرسائل النصية (OTP)   ← الحين «console»، سؤال ٥
                    └── تخزين خاص للمستندات (S3)     ← المرحلة ٣

  packages/shared ◄── يستخدمه الطرفين: الأقسام، وقواعد التحقق، وقواعد الطلب والإلغاء، والمبالغ
  packages/brand  ◄── يتولّد من brand/tokens.json
```

**على الاستضافة:** حاوية Docker وحدة (`Dockerfile`) فيها الخادم والموقع، وقاعدة بيانات PostgreSQL منفصلة عند نفس المزوّد.

## شاشات المصنع (apps/app/app): ٦ شاشات

حسب `docs/product.md` (القسم ٣). كانت ١٠ في المرحلة ١.

| # | الملف | الرابط | الشاشة |
| --- | --- | --- | --- |
| ١ | `login.tsx` | `/login` | الدخول: الجوال، ثم الرمز، ثم اسم المصنع وموقعه (أول مرة بس) |

| ٣ | `request/new.tsx` | `/request/new` | طلب جديد (و«اطلب مرة ثانية» يفتحها معبّية) |

## مسارات الخادم (apps/api), تحت `/api/v1`

| المسار | مين يقدر | وش يسوي |
| --- | --- | --- |
| `POST /auth/otp/request` | أي أحد (بحدود) | يرسل رمز تحقق للجوال |
| `POST /auth/otp/verify` | أي أحد (بحدود) | يتحقق من الرمز، وينشئ الحساب أول مرة، ويرجع رمز جلسة |
| `POST /auth/logout` | الداخل | يلغي الجلسة |
| `GET /me` · `PATCH /me` | الداخل | بيانات الحساب والمصنع · تغيير اللغة |
| `PUT /factory` | مستخدم مصنع | ينشئ المصنع أول مرة أو يعدّل بياناته |
| `GET /config` | أي أحد | سياسة الإلغاء، وهل وضع التجربة شغّال |
| `GET /requests` · `POST /requests` | مستخدم مصنع كمّل بياناته | طلبات مصنعه بس · رفع طلب |
| `GET /requests/:id` | نفسه | تفاصيل طلب من طلبات مصنعه، مع العروض والإجراءات المتاحة |
| `POST /requests/:id/seen` | نفسه | يعلّم العروض كمقروءة |
| `POST /requests/:id/accept` | نفسه | قبول عرض (`{ offerId }`) |
| `POST /requests/:id/cancel` | نفسه | إلغاء مجاني (قبل بدء التنفيذ) |
| `POST /requests/:id/cancel-request` · `/cancel-request/withdraw` | نفسه | طلب إلغاء بعد البدء · سحبه |
| `POST /requests/:id/dispute` | نفسه | فتح بلاغ إذا رفض المزوّد الإلغاء |
| `POST /requests/:id/confirm-receipt` | نفسه | تأكيد الاستلام |
| `GET /health` | أي أحد | فحص إن الخادم شغّال |

الأخطاء ترجع دائمًا بالشكل `{ "error": "رمز", "field"?: "...", "retryAfterSeconds"?: n }`، والتطبيق يترجم الرمز في `src/i18n/errors.ts`.

## كيف تتواصل الأجزاء

1. **الدخول:** التطبيق يرسل الجوال، والخادم يرسل رمز (الحين يكتبه في السجل). التطبيق يرسل الرمز، والخادم يرجع رمز جلسة. الجوال يحفظه في الخزنة المشفّرة، والموقع في تخزين المتصفح (`src/api/tokenStore.ts`). كل طلب بعدها يحمل `Authorization: Bearer <رمز>`.
2. **الصلاحيات:** `apps/api/src/auth.ts` يقرأ المستخدم من رمز الجلسة. `requireFactory()` يتأكد إنه مستخدم مصنع ويعطي رقم مصنعه، وكل استعلام في `services/requests.ts` مفلتر بهذا الرقم.
3. **قواعد الطلب:** `packages/shared/src/requests.ts` فيه الحالات والإجراءات المسموحة في كل حالة وسياسة الإلغاء. الخادم يتحقق منها قبل أي تغيير، ويرجع قائمة الإجراءات المتاحة (`actions`) مع كل طلب، والشاشة تعرض الأزرار حسبها.
4. **التحديث التلقائي:** وقت ما الطلب ينتظر شي (عروض، أو بدء المزوّد، أو رده على الإلغاء)، التطبيق يسأل الخادم كل ٣ إلى ٤ ثواني (`src/api/requests.ts`). بعدين ممكن نبدّلها بإشعارات فورية.
5. **الهوية → الكود:** `pnpm tokens` يقرأ `brand/tokens.json` ويكتب `packages/brand/src/tokens.generated.ts`. التطبيق يقرأ الألوان عن طريق `useTheme().colors`.
6. **اللغة والاتجاه:** `I18nProvider` يحدد اللغة (العربي افتراضي)، ويضبط `dir="rtl"` في الموقع و`I18nManager` في الجوال. النصوص في `strings.ts`.

## قاعدة البيانات

الشكل الكامل في `apps/api/prisma/schema.prisma` (مع شرح لكل جدول). الجداول الحالية:

| الجدول | وش يحفظ |
| --- | --- |
| `users` | كل من يدخل: الجوال، والدور (مصنع، مزوّد، موظف)، والحالة (نشط، موقوف)، واللغة |
| `otp_challenges` | رموز التحقق: **بصمة** الرمز، ووقت الانتهاء، وعدد المحاولات، وعنوان IP |
| `sessions` | جلسات الدخول: **بصمة** رمز الجلسة، ووقت الانتهاء، والإلغاء |
| `factories` · `factory_members` | المصانع، ومين تابع لأي مصنع (يسمح بأكثر من موظف لاحقًا) |
| `providers` | المزوّدين (نسخة مبسّطة تكتمل في المرحلة ٣). `is_demo` للوهميين |
| `requests` | الطلبات: القسم، والنوع، والتفاصيل، والحالة، وطلب الإلغاء، والبلاغ، وأوقات كل مرحلة |
| `offers` | العروض: السعر **بالهللة** قبل الضريبة، والحالة، ومتى شافها المصنع |
| `settings` | إعدادات تتغيّر بدون مبرمج (الحين: سياسة الإلغاء) |
| `audit_log` | سجل كل إجراء. **قاعدة البيانات تمنع تعديله أو حذفه** (trigger في أول ترحيل) |

## ملاحظات تقنية

- **الأيقونات:** نستورد كل أيقونة لحالها من `src/components/icons.ts`. `metro.config.js` يحوّل `@tabler/icons-react-native/icons/IconX` لملف الأيقونة نفسه. بدون هذا كانت المكتبة كاملة (آلاف الأيقونات) تنضم للموقع وحجمه يصير ٧ ميجا بدل ٢٫٤.
- **تقسيم الصفحات:** `asyncRoutes` مقفل في `app.json`، فالموقع ملف JavaScript واحد. هذا أبسط للنشر في هذي المرحلة.
- **بناء الخادم:** `apps/api/scripts/build.mjs` يجمع الخادم و`packages/shared` في ملف واحد (`dist/server.mjs`)، والمكتبات تبقى في `node_modules`.
- **ملفات مولّدة:** `apps/api/src/generated/` (عميل Prisma) يتولّد تلقائيًا بعد `pnpm install`، وما يدخل المستودع.
- **`packages/shared` بنوع `"type": "module"`:** ضروري عشان الخادم (Node) يقرأ تصديراته صح.
- **pnpm بإعداد `node-linker=hoisted`** (في `.npmrc`): React Native يحتاج الحزم مسطّحة في `node_modules`.
