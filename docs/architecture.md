# البنية التقنية

**آخر تحديث:** 21 نوفمبر 2026 (المرحلة ٢)

## الصورة العامة

```
                 ┌────────────────────────────────────────┐
  الموقع ◄───────┤  apps/app  (Expo + React Native)        │
  iPhone ◄───────┤  كود واحد للموقع وiPhone وAndroid        │
  Android ◄──────┤  ولوحة الإدارة لاحقًا تحت /admin          │
                 └──────┬───────────────────────┬─────────┘
                        │ HTTPS (JSON)          │ يقرأ الألوان والخطوط من
                        ▼                       ▼
  ┌──────────────────────────────┐   ┌─────────────────────────────┐
  │ apps/api (Node + Fastify)    │   │ packages/brand ◄── brand/tokens.json
  │ الدخول، والصلاحيات، والطلبات │   └─────────────────────────────┘
  └──────┬───────────────┬───────┘
         │ Prisma        │ واجهة SmsSender
         ▼               ▼
   PostgreSQL 16     مزوّد الرسائل (حاليًا: سجل الخادم للتطوير)

  packages/shared: قواعد التحقق (Zod) والأقسام وأكواد الأخطاء.
  يستخدمها التطبيق والخادم، فالقاعدة تُكتب مرة وحدة.

  لاحقًا: تخزين خاص للمستندات (S3، المرحلة ٣)، والفوترة الإلكترونية (المرحلة ٥).
```

**وش حقيقي ووش تجريبي في المرحلة ٢:**
- **حقيقي (في الخادم وقاعدة البيانات):** الدخول برقم الجوال ورمز التحقق، والجلسات، وبيانات المصنع، والطلبات (رفع، وقراءة، وإلغاء)، وسجل الإجراءات.
- **تجريبي (في ذاكرة الجهاز):** العروض، والفواتير، والتنبيهات، و٣ طلبات وهمية تبيّن دورة العروض كاملة. كلها عليها علامة «تجريبي». تصير حقيقية في المرحلة ٤ و٥.

## مسارات الخادم (apps/api)

| المسار | مين يقدر | وش يسوي |
| --- | --- | --- |
| `GET /health` | الكل | فحص الخادم وقاعدة البيانات |
| `POST /auth/otp/request` | الكل | يرسل رمز تحقق. نفس الرد دائمًا، سواء الرقم مسجّل ولا لا |
| `POST /auth/otp/verify` | الكل | يتحقق من الرمز. ينشئ المستخدم إذا جديد، وينشئ جلسة |
| `POST /auth/refresh` | صاحب مفتاح تجديد | يبدّل مفتاح التجديد ويعطي مفتاح دخول جديد |
| `POST /auth/logout` | الكل | يلغي الجلسة |
| `GET /me` | داخل | المستخدم ومصنعه |
| `PUT /factory` | دور «مصنع» | ينشئ أو يعدّل بيانات مصنع المستخدم |
| `POST /requests` | دور «مصنع» بمصنع مكتمل | يرفع طلب |
| `GET /requests` | دور «مصنع» | طلبات مصنعه، الأحدث أول، مقسّمة صفحات (`?limit=&cursor=`) |
| `GET /requests/:id` | دور «مصنع» | طلب من طلبات مصنعه، وإلا 404 |
| `POST /requests/:id/cancel` | دور «مصنع» | يلغي الطلب إذا «بانتظار العروض»، وإلا 409 |

**شكل الأخطاء:** `{ "error": "<كود>" }` مع تفاصيل حسب الحالة (`attemptsLeft`، `retryAfterSeconds`، `issues`). الأكواد في `packages/shared/src/errors.ts`، والتطبيق يحوّلها لرسائل في `apps/app/src/lib/errors.ts`.

## قاعدة البيانات (المرحلة ٢)

| الجدول | وش يحفظ |
| --- | --- |
| `users` | كل من يدخل: الجوال (`+9665…`)، والدور (`factory`/`provider`)، والحالة (`active`/`suspended`)، واللغة |
| `factories` | المصنع: الاسم، والمدينة، واسم المسؤول، والسجل والرقم الضريبي (اختياريين) |
| `factory_members` | ربط المستخدم بمصنعه (مستخدم واحد = مصنع واحد في هذي المرحلة) |
| `otp_challenges` | رموز التحقق: **بصمة** الرمز (مو الرمز)، وبصمة عنوان IP، وعدد المحاولات، والصلاحية |
| `sessions` | جلسة لكل جهاز: متى بدأت، ومتى تنتهي، وهل انلغت وليش |
| `refresh_tokens` | مفاتيح التجديد (بصمتها بس). كل مفتاح ينستخدم مرة وحدة |
| `requests` | طلبات المصانع: القسم، والنوع، والتفاصيل، والموقع، والموعد، والحالة |
| `audit_log` | سجل كل إجراء (مين، ووش، ومتى، وعلى أي شي). **الإضافة بس**: trigger في القاعدة يمنع التعديل والحذف والتفريغ |

المعرّفات UUID. الأوقات بتوقيت UTC. أي تغيير على القاعدة يكون بملف ترحيل جديد:

```bash
cd apps/api && DATABASE_URL=... npx prisma migrate dev --create-only --name وصف_التغيير
```

ثم راجع ملف SQL الناتج، وطبّقه بـ `pnpm db:migrate`.

## كيف تتواصل الأجزاء

1. **الهوية → الكود:** `pnpm tokens` يقرأ `brand/tokens.json` ويكتب `packages/brand/src/tokens.generated.ts`. التطبيق يقرأ الألوان من `useTheme().colors`.
2. **اللغة والاتجاه:** `I18nProvider` يحدد اللغة (العربي افتراضي) والاتجاه. النصوص في `strings.ts`.
3. **قواعد التحقق:** `packages/shared` فيه مخططات Zod. التطبيق يفحص فيها قبل الإرسال (رسالة فورية)، والخادم يفحص فيها مرة ثانية قبل الحفظ (هذا اللي يُعتمد عليه).
4. **الدخول (رمز التحقق):**
   1. التطبيق يرسل الجوال → الخادم يتأكد من الحدود، ويولّد رمز، ويحفظ بصمته، ويرسله.
   2. التطبيق يرسل الجوال والرمز → الخادم يحسب المحاولة أول (تحديث ذرّي)، ثم يقارن بوقت ثابت.
   3. إذا صح: يُستهلك الرمز، وينشئ المستخدم إذا جديد (دور «مصنع»)، وينشئ جلسة، ويكتب في السجل.
5. **الجلسة:**
   - **مفتاح دخول** قصير (15 دقيقة، JWT) يرسله التطبيق في رأس `Authorization` مع كل طلب. يبقى في الذاكرة بس.
   - **مفتاح تجديد** (30 يوم): في الجوال بالخزنة الآمنة (`refreshStore.native.ts`)، وفي المتصفح بكوكي `httpOnly` و`Secure` و`SameSite=Strict` على مسار `/auth` بس.
   - إذا رجع 401، `api.ts` يجدد مرة وحدة ويعيد الطلب. التجديد يبدّل المفتاح. واستخدام مفتاح قديم يلغي الجلسة كاملة (علامة سرقة).
   - التجديد والخروج بالكوكي يحتاجون رأس `X-Requested-With: mazood` (حماية من CSRF).
6. **الصلاحيات:** كل مسار محمي يمر على `requireAuth` (يتأكد من المفتاح ومن الجلسة في القاعدة ومن إن الحساب مو موقوف) ثم `requireRole`. المصنع يُعرف من الجلسة، وكل استعلام على الطلبات فيه `factoryId` المستخدم الحالي. طلب مصنع ثاني يرجع 404.
7. **الحدود (rate limiting):**
   - رموز التحقق: 3 لكل رقم كل 15 دقيقة، و10 باليوم، و20 لكل IP بالساعة. محسوبة من قاعدة البيانات، فتبقى صحيحة لو انعاد تشغيل الخادم.
   - مسارات الدخول: 30 طلب لكل IP كل 15 دقيقة. وحد عام: 300 طلب بالدقيقة لكل IP. هذي في ذاكرة الخادم (لو صار فيه أكثر من نسخة للخادم، تحتاج مخزن مشترك مثل Redis).
   - الأرقام كلها في `apps/api/src/auth/policy.ts`.
8. **السجلات التقنية** (pino): تخفي رأس `Authorization` والكوكيز وأي حقل اسمه `phone` أو `code` أو `refreshToken`. رسالة التطوير اللي فيها الرمز تعرض آخر ٤ أرقام من الجوال بس.

## الاختبارات

`pnpm test` يشغّل مشروعين في Vitest (الإعداد في `vitest.config.mjs`):

- **unit:** الهوية، والتنسيق، والمبالغ، ومنطق البيانات التجريبية، وقواعد التحقق المشتركة.
- **api:** الخادم كامل على قاعدة بيانات اختبار حقيقية. `test/global-setup.ts` يمسح القاعدة ويطبّق كل ملفات الترحيل قبل كل تشغيل، ويرفض يشتغل إلا على قاعدة اسمها ينتهي بـ `_test`. كل اختبار يستخدم أرقام جوال وعناوين IP عشوائية، فما تتداخل.

## ملاحظات تقنية

- **الأيقونات:** نستورد كل أيقونة لحالها من `src/components/icons.ts`. `metro.config.js` يحوّلها لملف الأيقونة نفسه (بدونه يصير الموقع ٧ ميجا).
- **ملفات `.native.ts`:** Metro ياخذ `refreshStore.native.ts` في iPhone وAndroid، و`refreshStore.ts` في الموقع.
- **`asyncRoutes` مقفل** في `app.json`، فالموقع ملف JavaScript واحد.
- **pnpm بإعداد `node-linker=hoisted`** (في `.npmrc`): React Native يحتاج الحزم مسطّحة. والحزم اللي تحتاج تشغّل سكربت عند التثبيت (Prisma وesbuild) مسموحة في `pnpm-workspace.yaml`.
- **Prisma 7:** العميل يتولّد في `apps/api/src/generated/` عند `pnpm install`، ويتصل بالقاعدة عن طريق `@prisma/adapter-pg`. عنوان القاعدة لأوامر Prisma في `prisma.config.ts`.
